About

I build and run the infrastructure behind a live commercial real-estate auction platform — Kubernetes, AWS, and the delivery pipelines that put code in front of bidders.

Most of my work is migrations that cannot afford downtime: a fifteen-service language re-platform, an ingress replacement across production clusters, a node-provisioning swap. Before those, a greenfield serverless product built from an empty account — and before that, the migration that first put this platform on managed Kubernetes at all. I care about making risky changes cheaply reversible, and about proving a fix worked with data rather than asserting it.

The thread through all of it is turning one-off work into shared assets: a build fix becomes the onboarding document, a rollout fix goes into the shared chart, a migration becomes versioned modules and a runbook someone else can run without me.

Secrets & Access Substrate for a New Service Fleet

Infrastructure owner · 2025–2026 · 15 services, 4 environments

Built the layer every service needed before it could start: secrets injected at runtime from a central vault instead of baked into images, cache and data-store access through workload IAM roles instead of static passwords, per-service message-bus credentials, and database delivery moved from manual scripts onto gated pipelines.

The durable win was removing long-lived static credentials from the runtime path — access became role-based and auditable, and standing up a service became a checklist rather than tribal knowledge.

Zero-Downtime Deploys, Fleet-Wide

One fix in the shared chart · 2026 · every consuming team

Rollout defaults retire old pods on a fixed delay, which can cut off requests still in flight — a failure mode that never trips an alert, so it goes unnoticed. I measured the real shutdown timing per service and set it in the shared chart rather than service by service, so every consuming team inherited it, then hardened two related resilience settings in the same pass. Confirmed by controlled load testing rather than by the absence of alerts.

Fleet Capacity, Cost & Node Provisioning

Infrastructure lead · 2024–2026 · multiple clusters, 15+ services

Replaced a third-party node provisioner with the CNCF-standard autoscaler across the fleet, staged over five months with production left to soak. The driver wasn't cost: it took a third-party dependency out of the cluster-provisioning critical path in favour of a CNCF-standard tool. Node pools designed explicitly — interruptible capacity for general workloads, reserved for critical ones — alongside the managed Kubernetes upgrades these clusters rode on, run under change control including for a vertical outside my own team.

On the workload side: hybrid autoscaling — schedules for predictable load, metrics as the safety net — CPU and memory right-sized from production telemetry, and cross-zone transfer cut with topology-aware routing. Off-hours non-production cost fell by roughly two thirds, though I reverted savings on several business-critical services before merge once load analysis showed peak-event demand needed the headroom.
